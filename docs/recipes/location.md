# 위치 기반 기능 (근처·동네 인증·지도)

## 먼저: 위치정보법 (사용자 결정)

한국에서 **개인위치정보**(특정 개인의 위치를 알 수 있는 정보)를 수집·이용하거나 이를 이용한 서비스를 제공하면
위치정보법상 **위치기반서비스사업 신고**(방송통신위원회) 대상이 될 수 있다. 미신고 운영은 처벌 대상이다.
이용약관에 위치기반서비스 약관, 개인위치정보 이용·제공 사실 확인자료 보관 등의 의무도 생긴다.

Claude 는 위치 기능을 만들기 전에 아래를 정리해 사용자에게 보여 주고 결정을 받는다(필요하면 전문가 확인 권장):

| 설계 | 개인위치정보? | 메모 |
| --- | --- | --- |
| 기기에서만 위치를 쓰고 저장·전송하지 않음(예: 현재 위치로 지도만 이동) | 서버 수집 없음 | 가장 가벼움 |
| 사용자가 고른 동네 **이름**만 저장(GPS 는 동네 판별에만 쓰고 버림) | 판단 필요 | 동네 인증 앱이 흔히 쓰는 방식 |
| 좌표를 서버에 저장·다른 사용자에게 거리 표시 | **해당 가능성 높음** | 신고·약관·보관 의무 |
| 실시간 위치 공유 | 해당 | 신고 필수 수준 |

결정은 `docs/decisions.md` 에 남긴다.

## 구현

- 🤖 네이티브 PR: `npx expo install expo-location` + `app.json` 권한 문구(한국어, 왜 필요한지):
  iOS `NSLocationWhenInUseUsageDescription`, Android 는 `ACCESS_COARSE_LOCATION`(정밀 위치가 꼭 필요할 때만 FINE).
  **백그라운드 위치는 요청하지 않는다**(심사가 매우 까다롭다). 개인정보 라벨/Data safety 에 위치 항목.
- 권한은 기능을 쓰는 순간에 요청하고, 거부해도 앱의 나머지는 동작해야 한다(직접 동네 선택 대안).
- 정밀도를 일부러 낮춘다: 동네 판별이면 좌표를 소수 2~3자리로 반올림하거나 행정동 코드만 저장.
- 거리 검색은 PostGIS(`create extension postgis` — Risk `security.db-extension`)와 `st_dwithin` RPC. RPC 는 좌표를
  그대로 돌려주지 않고 거리 구간(“1km 이내”)만 돌려준다.
- 지도: `react-native-maps`(Google 지도 키 필요 — Android 는 API 키를 `app.json` 에, 키 제한 설정) 또는 카카오맵(WebView/SDK) —
  비용·키 발급이 있어 먼저 묻는다.
- 웹: `expo-location` 은 브라우저 위치 API 로 동작한다. 지도 컴포넌트는 `*.web.tsx` 대안이 필요할 수 있다.
